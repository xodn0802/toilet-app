**배포** — https://toilet-app-azure.vercel.app/

> 이 문서는 초기 기획·명세다. 각 표의 **상태** 칸이 지금 실제로 되는 것을 말한다.
> 결정의 근거와 개발 기록은 [CLAUDE.md](CLAUDE.md) 에 있다.

## 0. 지금 되는 것 (2026-08-17)

- **전국 공중화장실 51,128곳**이 실제 좌표로 지도에 뜬다. 공공데이터가 좌표를 주지
  않아 주소를 지오코딩해 채웠다 (적재 52,751건 중 97.0% 성공).
- **「바로 안내」 버튼 하나로** 1km 이내 가까운 5곳 중 평점이 가장 높은 곳까지
  경로를 그린다. 왜 그 곳인지도 배너가 같이 말한다.
- 현재 위치를 기준으로 `1km 이내 N곳`을 세고, 한 곳을 고르면 **도보 경로**를 그린다.
  위치 오차가 크면 점 대신 오차 반경 원을 그리고 거리를 주장하지 않는다.
  도보 경로를 못 받으면 **점선으로 방향과 직선거리만** 알린다.
- **좌표가 같은 화장실은 하나로 묶어 개수 배지**를 달고, 누르면 **청결도 순
  목록**으로 펼친다. 캠퍼스처럼 한 점에 71곳까지 쌓이던 것이 이제 전부 눌린다.
  평가가 없는 곳은 0점이 아니라 **원래 순서대로 뒤에** 선다.
- 화장실마다 **남자·여자·공용**을 구분한다. 같은 건물 같은 층의 남/여가 각각
  한 곳으로 선다 — 캠퍼스 실내 화장실은 그게 기본이다.
- 상세에서 시설 정보·평균 별점·청결도·리뷰를 보고 **리뷰를 등록**할 수 있다.
- **로그인 화면이 없다.** 리뷰를 남기는 순간 익명 신원이 생긴다 (P0 7번 참고).
- 공공데이터에 없는 화장실은 **제보**할 수 있고(건물·층·남녀까지), 검토를 거쳐
  올라간다. 목록·상세의 **「이 위치에 화장실 추가」** 는 좌표·주소·건물을 채운
  폼을 바로 열어, 빠진 층 하나를 본 사람이 그 자리에서 보탤 수 있다.
- **내가 보낸 제보는 그 자리에 점선 핀으로 남는다.** 검토 중이라는 뜻이고,
  승인돼 지도에 오르면 스스로 사라진다.
- 주소에 좌표를 넣으면(`?lat=&lng=&level=`) **거기서 지도가 열린다.** 사이드바의
  **「인하대 화장실」** 이 그 링크다.
- 데스크톱은 사이드바 + 지도 위 상세 카드, 모바일은 드로어 + 하단 시트.
- 테마는 **라이트·다크·시스템** 3단.
- 링크 미리보기 카드·홈 화면 아이콘·개인정보 처리방침·방문 통계까지 붙어 있다.

**아직 안 되는 것** — 사진 업로드(P0 6번), 검색·필터·즐겨찾기(P1). 인하대 캠퍼스는
`scripts/data/inha-toilets.csv` 에 두 곳(정석 지하 1층·하이테크관 2층 남자)이
적혀 있고, **`npm run seed:campus` 를 돌려야 지도에 올라간다.**

## 1. 프로젝트 개요

### 1.1 한 줄 정의

낯선 곳에서 급하게 화장실을 찾는 사람을 위한, 가까운 화장실 위치와 "실제로 쓸 만한지"(청결도·편의시설·이용조건)를 함께 알려주는 지도 앱.

### 1.2 문제 정의

- 급할 때 주변에 화장실이 어디 있는지 모른다.
- 지도 앱은 위치는 알려줘도 지금 열려있는지·깨끗한지·남녀공용인지는 모른다.
- 상가 화장실은 정보 자체가 없어 헛걸음하고, 결국 카페에 눈치보며 들어가거나 검색으로 헤맨다.

### 1.3 솔루션

| 문제           | 해결 기능                                                           |
| -------------- | ------------------------------------------------------------------- |
| 위치를 모름    | 공공데이터 기반 주변 화장실 지도 + 길찾기                           |
| 상태를 모름    | 마커 상세에 필수 정보(남녀공용·변기 수·개방시간·편의시설) 즉시 표시 |
| 쓸 만한지 모름 | 사용자 크라우드소싱 리뷰(청결도 별점·사진·상태 태그)                |
| 커피값 아까움  | 이용조건 태그(무료/개방/음료구매/유료) + 무료·개방 화장실 우선 노출 |

## 2. 핵심 사용자 (페르소나)

- **낯선 지역 이동이 잦은 사람** (여행·출장·외근): 주변에서 급히 화장실을 찾음
- **유아 동반 부모·노약자**: 기저귀 교환대·장애인 화장실 등 조건이 중요
- **재학생(캠퍼스)**: 처음 가는 건물에서 화장실 위치를 모름 — 확장 기능 대상

## 4. 화면 구성 (예상 스크린 리스트)

1. 온보딩/로그인
2. 지도 홈 — 주변 화장실 + 현재 위치
3. 화장실 상세 — 정보 + 리뷰 열람
4. 리뷰 작성 — 별점·상태 태그·사진
5. 길찾기 — 경로 화면
6. 필터
7. 검색
8. 즐겨찾기 목록
9. 마이페이지 — 내 리뷰·즐겨찾기
10. (확장) 화장실 추가 / 캠퍼스 건물·층 뷰

**실제로는 화면 수가 훨씬 적다.** 지도 하나에 거의 다 얹혀 있다.

- 2·3·4·5는 **지도 홈 한 화면**이다. 상세는 모바일에서 하단 시트, 데스크톱에서
  지도 위 카드로 뜨고 리뷰 작성도 그 안에 있다. 길찾기는 별도 화면 없이 지도에
  경로를 그린다. 화장실 추가(10)도 지도 위에 얹는 모드다 — 라우트를 옮기면
  지도가 다시 만들어져 보던 위치·축척을 잃는다.
- **1번 온보딩/로그인은 안 만들었다.** 로그인이 없기 때문이다.
- 6·7·8·9는 아직 없다(P1).
- 대신 명세에 없던 **소개 페이지**(`/about`)와 **사이드바**가 생겼다. 좌표가 같은
  화장실을 펼치는 **목록 시트**도 지도 위에 얹는 방식이라 별도 화면이 아니다.

## 5. 기술 스택 (실제 채택)

| 영역             | 기술                                  | 메모                                                              |
| ---------------- | ------------------------------------- | ----------------------------------------------------------------- |
| 프론트엔드       | Next.js 16 (App Router) + Tailwind v4 | 색은 `app/globals.css` 한 곳에서만 정한다                         |
| 지도             | 카카오맵 JS SDK                       | 표시·마커·폴리라인. 네이버는 안 썼다                              |
| 지오코딩         | 카카오 REST (주소 → 좌표)             | 공공데이터가 2025년 2월부터 좌표를 안 준다                        |
| 도보 경로        | **TMAP 보행자 경로 API**              | 카카오모빌리티 길찾기는 자동차 전용이고 JS SDK엔 경로 탐색이 없다 |
| 백엔드           | Next.js API Routes                    | TMAP 키를 숨기는 프록시 한 개(`app/api/walk-route`)               |
| DB·인증·스토리지 | Supabase                              | RLS로 권한을 건다. 인증은 **익명**, 스토리지는 아직 안 쓴다       |
| 공공데이터       | 행정안전부 공중화장실정보 조회서비스  | 개발계정 일 10,000건. 지역 필터 없이 전량 수집한다                |
| 방문 통계        | Vercel Web Analytics                  | 쿠키를 안 써 동의 배너가 없다. 대시보드에서 켜야 쌓인다           |
| 배포             | Vercel                                | main 에 push 하면 자동 배포                                       |

## 6. 남은 일

처음 적어 둔 다음 액션 넷(키 발급 · 스키마 설계 · 지오코딩 파이프라인 · 지도 홈)은
전부 끝났다. 데이터 전국 확대와 마커 겹침도 2026-08-10 에 끝냈다.
`0004_building_floor.sql` 은 2026-08-15 에 적용됐다.

**출시하려면 사람이 해야 하는 것 셋** — 코드로는 못 한다.

1. `supabase/migrations/0005_gender.sql` 을 Supabase SQL Editor 에서 실행.
   **적용 전까지는 제보 등록과 `npm run seed:campus` 가 둘 다
   `column toilets.gender does not exist` 로 실패한다.**
2. `npm run seed:campus` 로 인하대 2건을 넣는다. 나머지 건물은 **학생 제보로
   채운다** — 전 건물을 다 채울 필요는 없다. 직접 더 넣고 싶으면
   `scripts/data/inha-toilets.csv` 에 줄을 더하고 다시 돌리면 된다(중복 안 생김).
3. Vercel 대시보드에서 **Web Analytics 켜기.**

그리고 홍보 전에 **실제 휴대폰의 에브리타임 인앱 브라우저에서 위치 권한**이
동작하는지 확인해야 한다. 자동화로는 검증할 수 없다.

**그 다음 남은 것**

- **사진 업로드 (P0 6번)** — 마지막 남은 P0. 익명 신원에는 부적절한 사진의 책임을
  물을 수 없어 **신고·삭제 절차가 같이 와야 한다.**
- **TMAP 도보 경로 일 1,000건** — 유일한 실질 병목이다. 넘으면 직선 점선으로
  떨어진다. 실사용량을 보고 캐시·한도 상향을 정한다.

## 7. 운영 부담

- **제보가 들어오면 Supabase 대시보드에서 SQL 로 승인**해야 지도에 뜬다. 승인 UI 는
  안 만들었다. 쿼리는 **가장 나중 마이그레이션 주석이 정본**이다 — 지금은
  `supabase/migrations/0005_gender.sql`. 컬럼이 늘 때마다 거기로 옮겨 적는다.
- DDL 은 코드에서 못 돌린다. 새 마이그레이션은 Supabase SQL Editor 에 직접 붙여
  실행해야 한다.
